# We Built a Database That Cannot Read Your Data

> "When everyone lies, INDB remembers what you saw."

INDB is not a database. It's an **epistemological engine** — a system designed to preserve truth in the age of manipulation.

## The Problem

How do you maintain objective reality when collective gaslighting can rewrite history? When PDFs can be edited, logs altered, timestamps faked?

## The Approach

Treat data as a **biological process**: inhale, exhale, axiom.

- **Inhale** — accept raw, chaotic reality. Multi-protocol (UDP, gRPC, HTTP, WebSocket). No judgment. <1ms latency.
- **Exhale** — compress truth, purge noise. Reputation is gravity. Lies become waste heat.
- **Axiom** — what remains is Ed25519-signed, immutable.

## The Cognitive Layer

Five modules, no one else has this stack:

- **Prism** — paradox-aware synthesis. Returns competing readings, perception gap. Paradox as signal, not error.
- **Echo** — resonance detection. Token + emotion + location. Find "who else feels like this?"
- **Instinct** — adrenaline reflexes. Three modes from deep analysis to lightning reflex.
- **Deduction** — evidence chains. Seeds → Echo expansion → temporal/spatial/token inference → conclusion.
- **Blind** — zero-knowledge storage. `blind_payload` is encrypted before it touches the server. We store it. We never read it. No key. No backdoor. Architecturally.

## The Black Box Contract

When you use `blind_payload`:
- You may hide what is inside.
- You may not hide that you were here.

`timestamp` and `location` become mandatory. The system proves *presence* without revealing *content*. For authorities: "Something was here. This location. This time." What it was — unknown. By design.

## Use Cases

Legal evidence. Healthcare audit. Financial compliance. Journalism. IoT. Anywhere you need: prove it happened, prove it wasn't changed, protect what's inside.
